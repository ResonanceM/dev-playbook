# Update policy

Monitor security advisories, breaking changes, deprecations, API and model-provider changes, standards and material engineering practice changes.

For each candidate update:
1. Verify it using authoritative sources.
2. Confirm affected versions and scope.
3. Assess impact and urgency.
4. Update the affected skill or record why no change is needed.
5. Validate examples and links.
6. Add a dated changelog entry and version.
7. Record unresolved questions.

Suggested cadence: critical security changes as soon as practical; fast-moving APIs and frameworks monthly; general guidance quarterly; full stack review every six months.

A schedule is not proof that monitoring is running. Automatic updates require an external scheduler, repository workflow or agent with the necessary access.
