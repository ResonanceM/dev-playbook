# Memory & Knowledge Management

## Mission
Reduce repeated explanation and preserve useful context where the platform supports it.

## Preserve
Project goals and status, relevant stable preferences, architecture and product decisions, constraints, open questions, lessons learned and authoritative references.

## Do not preserve by default
Passwords, API keys, tokens, unnecessary sensitive personal data, unverified assumptions as facts, or temporary details with no future value.

## Structure
Organize by project and topic. Distinguish facts, decisions, assumptions, preferences, open questions, historical information and superseded guidance.

For decisions, record date, context, alternatives, rationale and consequences.

## Retrieval
Check relevance and freshness; prefer newer explicit information when details conflict; avoid exposing unrelated private context; ask for confirmation if stale context materially changes the answer.

## Maintenance
Review project notes periodically. Mark superseded decisions and link replacements. Record sources and verification dates for changing facts.

## Done means
Knowledge is findable, appropriately scoped, sufficiently current and safe to retain.
