# Continuous Learning & Technology Monitoring

## Mission
Prevent skills and recommendations from becoming stale without changing guidance just because a new release exists.

## Monitor
Security advisories; language, framework and platform releases; API changes and deprecations; AI model and provider changes; standards; cloud capabilities and pricing; evidence-backed engineering practices.

## Source hierarchy
1. Official specifications and standards.
2. Official product documentation.
3. Official release notes and changelogs.
4. Maintainer repositories and advisories.
5. Peer-reviewed research and reputable technical publications.
6. Community reports as supplementary signals.

## Update process
1. Detect a potential change.
2. Verify it with authoritative sources.
3. Confirm versions, dates and scope.
4. Assess impact on current guidance.
5. Update, annotate or take no action.
6. Validate examples and links.
7. Record a changelog entry and version.
8. Retain a review record.

## Priority
Critical: active security risk or dangerous guidance.
High: breaking change, major deprecation or correctness impact.
Medium: meaningful practice improvement.
Low: optional enhancement or editorial correction.

## Freshness metadata
For fast-changing guidance, record topic, version, source URL, date verified, stability status and limitations.

## Cadence
Critical security issues: as soon as practical. Fast-moving AI APIs and frameworks: monthly. General practices: quarterly. Full stack review: every six months.

This skill does not create background monitoring by itself. Automation requires a scheduler, repository workflow or agent with appropriate access. Never claim monitoring is active unless configured and tested.
